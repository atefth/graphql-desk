# Configuration, CLI and generated-state contract

Requirements contract for PLAN-02 and PLAN-06. Production foundations are tracked in [feature status](../feature-status.md); no broad acceptance gate has passed. These requirements supplement the [parity plan](../parity-plan.md), retaining every upstream capability through Python equivalents. Optional persistent acceleration must never become a requirement for schema or live operation typing.

## Configuration decisions

Canonical project configuration is `[tool.graphql-desk]` in `pyproject.toml`. `graphql-desk --config PATH` selects an explicit pyproject; otherwise CLI searches from its working directory upward for the nearest pyproject containing this table. The editor resolves each source to the nearest configured workspace project, stopping at the workspace boundary. A project with no table stays inactive in the editor, rather than showing schema errors in unrelated Python files. Nested projects are independent; files cannot be owned by two projects. No implicit execution/import of Python configuration.

Precedence: command options override their corresponding project keys for that command only; project configuration overrides editor fallback configuration as a whole, without merging individual schema credentials from editor settings. Editor fallback uses a `graphqlDesk.project` object with the same validated shape and workspace-relative paths. User presentation preferences do not change semantic results. There is no implicit environment override; only header values explicitly written as `${env:NAME}` resolve environment variables. Missing variables fail with the variable name, never the secret. Relative paths resolve against the selected pyproject directory (CLI `--output` resolves against working directory); `${configDir}` means that directory. Reject unknown substitutions and unknown keys with a diagnostic.

| Python configuration key | Default / validation | Upstream disposition |
|---|---|---|
| `schema` | Required unless `schemas` is present; SDL/introspection path, HTTP(S) URL, or `{url, headers}`; headers string map | `schema`; authenticated remote loading retained |
| `schemas` | Absent; nonempty array of `{name, schema, schema_output, persisted_output?, cache_output?, scalars?, enums?, disable_masking?}`; unique names and outputs | Named multi-schema selection retained; mutually exclusive with single-schema fields |
| `generated_package` | `graphql_desk_generated`, importable package directory under the project root; require a valid Python package identifier and reject paths outside the project | Python generated schema/factory binding |
| `schema_output` | Required for configured editor/type generation: explicit writable `.pyi` path inside `generated_package`; one-off stdout/schema conversion may omit it | `tadaOutputLocation`; Python schema metadata/type output |
| `persisted_output` | Absent; required when generation has no explicit output/stdout destination | `tadaPersistedLocation` |
| `cache_enabled` | `false`; optional acceleration only; enabling before support exists produces an explicit configuration error | Optional persistent cache |
| `cache_output` | Absent; required if optional persistent cache is enabled | `tadaTurboLocation`; optional acceleration only |
| `template` | Absent; additional imported callable identity to recognize alongside supported graphql factories; resolution must not execute imports | Additional authoring callable, retained in Python form |
| `track_field_usage` | `true` | `trackFieldUsage` |
| `check_colocated_fragments` | `true` | `shouldCheckForColocatedFragments` |
| `client_directives` | `[]`; names without `@`; suppress schema-unknown errors only, never fabricate directive execution or selection semantics | `clientDirectives` |
| `schema_refresh_interval` | `0` seconds (explicit refresh only); positive seconds enables remote polling after workspace trust; negative/nonfinite values rejected | Remote schema update capability |
| `disable_preprocessing` | `false`; changes generated schema representation only; public types/results identical | `tadaDisablePreprocessing` and CLI switch |
| `scalars`, `enums` | Empty maps; import-qualified static type expressions, never eval; exact builtin/default semantics in typing contract | Schema setup custom mappings, both input and output |
| `disable_masking` | `false` | `disableMasking`; preview upstream behavior retained |
| `source_roots`, `include`, `exclude`, `entrypoints` | Exact defaults and matching rules below | Python source/project analogue of TypeScript project ownership |

`templateIsCallExpression` is fixed true: Python call expressions are required, tagged templates have no Python syntax. Setting false is a configuration error explaining the equivalent, not silently ignored. `global`/`editorContributed` are internal upstream instance-routing flags, replaced by one owning Python editor instance per project; they are not user keys. Multiple schema records may not resolve to the same output. All generated output sharing across projects is rejected, including schema output; each project owns its generated bindings. This deliberately stricter collision policy avoids clobbering project-specific imports and types while preserving equivalent separate schema outputs. Normalize Windows path case and resolve symlinks before collision checks. Do not expose credential identities in logs.

## Commands and option dispositions

Executable: `graphql-desk`; equivalent `python -m graphql_desk`. `--config/-c` replaces `--tsconfig/-c` throughout. Help and version are available without loading a project. `generate output`, `generate schema`, `generate persisted` are accepted aliases. Every command validates configuration before mutation. stdout contains only requested artifacts/machine reports when redirected; diagnostics go to stderr. Successful execution exits 0; GraphQL errors, failed warning policy, configuration/IO/network failures exit nonzero. Display filtering does not hide errors from exit status.

| Upstream command | Python command and retained options/defaults |
|---|---|
| `check` | `check --config/-c --fail-on-warn/-w --level/-l info\|warn\|error`; level `info`, warning policy false |
| `generate-output` | `generate-output --config/-c --output/-o --disable-preprocessing`; configured schema output otherwise; piped output is Python stub text. Hidden upstream `--force-ts-format` becomes unnecessary: no TypeScript format exists and it is rejected with migration guidance |
| `generate-schema SCHEMA` | `generate-schema SCHEMA --config/-c --output/-o --header 'Name: value'` (repeatable); input URL/SDL/introspection JSON, deterministic SDL output. Default destination is configured local schema path, otherwise stdout when redirected, otherwise a missing-destination error; never overwrite a remote origin |
| `generate-persisted` | `generate-persisted --config/-c --output/-o --disable-normalization --fail-on-warn`; booleans false; destination configured persisted output or redirected stdout, otherwise error; normalized text default |
| `scan` | `scan --config/-c --format/-f json --graph --output/-o --fail-on-warn/-w`; interactive terminal report otherwise; pipe/output implies JSON, graph implies machine graph. Experimental-equivalent maturity |
| `init [dir]` | `init [dir]`; directory defaults cwd; writes minimal schema/output config and setup instructions without overwriting existing keys/files; conflicts abort with a proposed edit. Upstream WIP-equivalent setup, no silent package installation |
| `doctor` | `doctor --config/-c`; checks effective config, schema access, interpreter/checker/editor versions, stub import ownership and bridge health; redacted actionable report, failure exit nonzero. Upstream WIP-equivalent |
| `turbo`, `generate turbo` | Optional only. If delivered, `turbo --config/-c --output/-o --fail-on-warn/-w`; disabled/enabled identical semantic output. Until delivered clearly report unsupported optional acceleration; no impact on parity release eligibility |

For multiple projects/schemas, generation uses each configured destination. A single explicit `--output` or stdout target with multiple outputs is rejected rather than merged ambiguously; select one project with `--config` and one schema with Python-native `--schema NAME`. This additional selector applies to generation and checking; unknown names fail. Schema refresh watches local schema files and uses explicit refresh for remote schema by default; `schema_refresh_interval > 0` enables authenticated polling at that interval after trust is granted. Retry transient fetches on explicit refresh and expose stale state; never silently substitute a different schema.

## Package, callable and internal API map

The [pinned root export list](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/index.ts) maps to `graphql_desk`: `parse`, `graphql`, `init_graphql`, `read_fragment`, `mask_fragments`, `unsafe_read_result`; `graphql.scalar` and `graphql.persisted` remain bound methods. `ResultOf`, `VariablesOf`, `FragmentOf`, typed document and persisted document types map to generated Python aliases and generic document protocols as specified in the API/type contract. `setupSchema`/`AbstractSetupSchema` become declarative schema configuration; `GraphQLTadaAPI` becomes the initialized factory protocol; `parseDocument` becomes the parser AST typing contract. `setupCache`/`AbstractSetupCache` belong only to optional acceleration. `DocumentDecoration`, `$tada`, `__mapType` receive Python document metadata/type mapping equivalents as needed to expose the same types; TypeScript isolated-module symbol mechanics require no Python namespace sentinel. No runtime wrapping/coercion is implied by these type surfaces. `graphql_desk.testing.read_result` preserves safe fixture functionality; editor integration replaces `./ts-plugin`; package version/metadata replaces `./package.json`.

Important source-versus-package distinction: [`gql.tada/cli`](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/cli/index.ts) starts the CLI; do not claim it exposes named callable generators. The separate [cli-utils API](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/packages/cli-utils/src/api.ts) exposes `generateOutput`, `generatePersisted`, `generateSchema`, `generateTurbo`, `scan`. Python-native `graphql_desk.cli` provides `generate_output`, `generate_persisted`, `generate_schema`, `scan`, and optional `generate_turbo`, using keyword arguments corresponding to the command options (snake_case), plus `silent=False` for schema/output generators. They return `None`, raise structured errors on failure and never terminate the host process. Command dispatch is `main(argv=None) -> int`; import does not execute it. This is a useful explicit Python equivalent, not a claimed root upstream named export.

[`./internal`](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/packages/internal/src/index.ts) is an advanced surface without a stability promise. Python `graphql_desk.internal` retains equivalent capabilities with snake_case names: `load_from_sdl`, `load_from_url`, `get_url_config`, `load`, `load_ref`; `parse_config`, `validate_unique_output_locations`, `get_schema_names_from_config`, `get_schema_config_for_name`; `load_config`, `load_configs`, `find_config_file`, `read_config_file` replace TS config functions; `resolveTypeScriptRootDir` becomes Python project-root discovery. `TSError` becomes checker integration error, `TadaError` becomes GraphQL Desk error. `minify_introspection`, `preprocess_introspection`, `output_introspection_file`, `extract_introspection_header` retain schema output operations. Loader/result/reference/update/error/config option interfaces become typed Python records/protocols; introspection feature probes remain loader implementation details because they are not re-exported by this internal entrypoint. No promise to reproduce JavaScript module structure or TypeScript compiler objects.

## Generated-state lifecycle and failure policy

The generated package owns paired runtime `.py` and static `.pyi` modules, including schema bindings and schema-bound factory imports with per-literal/per-operation overloads. User Python imports that generated factory; root helper calls do not magically gain literal-specific checker inference. Runtime `.py` modules delegate to the ordinary runtime factory/document implementation and never embed unsaved overlays. The paired module paths derive deterministically from `schema_output` (same basename), with an owned package initializer; no separate operation-output knob is needed. Live overloads are regenerated inside the bound schema module. The saved generated output is deterministic, generator-owned output with an ownership header, source/config/schema fingerprint and format version. User files, user-authored stubs and dirty generated buffers lacking matching ownership must never be overwritten. Generation writes complete validated temporary files then replaces the prior owned outputs with a generation manifest committed last; readers reject mismatched generation identifiers and recovery restores the last complete pair; failure preserves disk output and emits an error. No broad deletion or cleanup outside explicitly owned outputs. Source/config/schema are authoritative; generated files are disposable outputs, never the source for recovering lost user edits.

For the live bridge, model each project generation as `(source URI + document version, dependency versions, schema fingerprint, config fingerprint)`. Debounce/coalesce edits; cancellation prevents older jobs publishing after newer ones. Before publishing recheck all versions, ownership and project identity. Dependencies include fragments across files and scalar/schema config. The user-authorized live bridge may write generated stubs into a managed directory inside the trusted owning workspace. This supersedes the earlier unsaved-overlay-only restriction for owned generated analysis files. Preserve every pre-existing file and dirty user buffer; refuse foreign paths, changed ownership and stale source/project facts. Serialize publication, retain rollback safety and clean up only matching owned outputs across save/discard/undo/redo/close/reopen/delete/rename/restart/interpreter changes. This authorization does not establish lifecycle acceptance. A virtual URI or disk watcher alone is not presumed Pylance-compatible. The bridge must not rewrite user Python sources on each keystroke or treat private Pylance internals as a supported extension API.

| Event | Required outcome |
|---|---|
| Valid unsaved operation/fragment edit | Publish matching new types and GraphQL diagnostics; dependent hovers/checker errors converge without source save |
| Invalid/incomplete operation | Report source parse/validation error; mark affected operation unavailable and publish a deliberately unusable error type rather than stale success or permissive `Any`; unaffected valid operations stay usable |
| Invalid schema/config | Mark entire affected schema unavailable; do not present old types as current. Keep last good disk artifact for recovery, labeled stale in editor status |
| Save | Regenerate from saved project snapshot; only persist outputs matching that snapshot. Unsaved dependent buffers stay live overlays and never leak into committed disk output |
| Undo/redo or external source change | Treat as new versions, recompute dependencies; stale jobs cannot win |
| Source close | Replace its unsaved overlay with disk content (or remove if nonexistent), invalidate dependents; closing generated output alone must trigger bridge repair/reopen without user source edits |
| Delete/rename/project move | Invalidate source identities, rebind imports/config, remove only matching owned obsolete artifacts after successful replacement; no stale document binding |
| Restart/checker restart/interpreter change | Rebuild state from sources/config; verify active interpreter/stub roots and reconnect bridge; no cached type trusted without fingerprints |
| Timeout/crash/network failure | Visible degraded/unavailable status with retry; do not swallow diagnostics or claim fresh typing; recovery produces current versions only |

On deactivation, restore owned generated buffers to their saved contents without changing user-owned dirty data or forcing saves. Any save prompt or document dirty-state leak attributable to live overlays fails the broad bridge gate. Reject architecture choices that can only deliver the narrow hover proof but cannot satisfy this lifecycle. If supported VS Code APIs cannot safely achieve these outcomes, the implementation must revisit its bridge design before claiming live parity; this is an implementation acceptance risk, not proof that the design works.

Workspace trust: in restricted workspaces allow static local text inspection only; no interpreter/process launches, remote schema fetch, extension-driven file writes or import execution. After trust is granted revalidate state before activating. CLI invocation is explicit user execution, but still never imports project modules for discovery. Header values, schema authorization and environment secrets must be redacted from logs, diagnostics and generated metadata.

## Cross-contract decisions from final review

### One generated layout and omission invocation

`generated_package` defaults to `graphql_desk_generated`, a directory below the configured project root and a valid dotted Python package name (dots map to subdirectories). It owns its initializer and all generated descendants. Single schema identity is `default`; named schemas use their validated identifier. Schema factory/runtime plus schema declarations live at `<package>/<schema>.py` and `.pyi`; `schema_output` must point to that `.pyi`. Per-source aliases live at `<package>/sources/<source_module>.py` and `.pyi` (package/module identity relative to source root). Persisted constants live at `<package>/persisted/<schema>.py` and `.pyi`. Distinct source roots may not produce identical module identities; diagnose instead of inventing path-dependent aliases. No user module gets a generated replacement stub. The generation ownership manifest records every file/fingerprint; all commands use these paths.

`generate-output` generates the owned schema/factory and source-alias modules. `generate-persisted --omit-runtime-source` additionally writes ID-only persisted modules at the fixed layout after manifest validation; without that flag retain document definitions. No new optional path naming scheme. Existing `persisted_output` chooses the server JSON manifest; it does not choose Python module names. `check --artifact PATH.whl` is a Python-native build verification mode: examine the ZIP member list/generated module AST and declared ownership manifest without importing wheel code; reject missing generated pairs, retained operation/fragment strings, authoring module inclusion or imports of excluded authoring modules. Return nonzero on failure and do not modify the wheel.

Omission uses configured `authoring_roots` (default empty; required nonempty with `--omit-runtime-source`) containing dedicated Python GraphQL declaration modules, separately from application modules. They participate in `source_roots`/discovery, but must be excluded by the user's wheel builder. Standard build sequence: generate/validate manifest and ID-only modules; build wheel using project build tool including application/generated package but excluding authoring roots and server manifest; run `check --artifact wheel-path`. Omission generation fails if application modules statically import authoring modules rather than generated persisted constants, or if opaque/dynamic imports prevent proving separation. Mixed application/authoring modules are unsupported for omission until moved to a dedicated authoring module; retained mode remains available and ordinary embedded authoring stays core. No authored file rewriting or custom wheel builder is introduced. Artifact checks cannot prove malicious dynamic loading never reconstructs source; the supported build contract excludes dynamic authoring access explicitly.

### Scalar/enum configuration

`scalars` values are either an import-qualified type string applying to both directions, or a table `{input = "module.InputType", output = "module.OutputType"}` with exactly those keys. Example: `DateTime = {input = "builtins.str", output = "datetime.datetime"}`. Resolve symbols statically; never import/eval the user's module. Built-in mappings follow API/types contract. `enums` maps a schema enum name to an import-qualified static type string, used for both input and output; absent mapping uses `Literal` schema value strings. Configured enum remapping deliberately replaces that literal-union type (matching upstream's configurable mapping), without runtime conversion/validation. Literal GraphQL enum validation still uses schema values. Missing/ambiguous imports or wrong map shapes are configuration errors. This explicitly supersedes any unqualified “enums are always Literal” shorthand in the API contract.

### Discovery key syntax and defaults

`source_roots = ["."]`, `include = ["**/*.py"]`, `exclude = ["**/.git/**", "**/.venv/**", "**/venv/**", "**/__pycache__/**", "**/site-packages/**", "**/build/**", "**/dist/**"]`; generated package/owned build paths are always excluded even if included by a glob. Each root resolves relative to config directory; overlapping roots are deduplicated by canonical file identity. Patterns use `/` separators relative to each root, `*` within a component, `**` across zero or more components, `?` for one character; no implicit regex, brace expansion, negation or gitignore inheritance. Match full relative path, case-sensitive on every platform for reproducibility; canonical file dedup handles Windows case aliases. Files must match include and no exclude. Root must lie within the owning project/workspace unless explicitly selected by CLI project config; symlink traversal cannot escape configured roots. `entrypoints` defaults absent (graph indegree-zero roots); configured list contains exact root-relative Python module paths, not globs; unknown/excluded entries fail configuration. `authoring_roots` uses config-relative directories and must lie under source roots. These defaults govern editor, CLI, scan and persisted collection identically.

### GitHub Actions diagnostics

When `GITHUB_ACTIONS` is exactly `true`, emit each current diagnostic once as an Actions workflow annotation in addition to normal human reporting: error→`::error`, warning→`::warning`, info→`::notice`. Include workspace-relative `file`, 1-based `line`/`col` and exclusive end converted to inclusive `endLine`/`endColumn` where meaningful; omit unavailable fields rather than inventing location zero. Escape `%` as `%25`, CR/LF as `%0D`/`%0A`; also escape `:` and `,` in annotation property values as `%3A`/`%2C`. Never put secrets in messages/properties. For human `check` output, emit workflow commands on stdout as documented by GitHub. For artifact/JSON output, suppress inline workflow commands; Python-native `--annotations-output PATH` writes the commands to a separate file, which a subsequent CI step prints to stdout. This preserves pure machine stdout without assuming GitHub recognizes stderr commands. CI annotations follow severity display filtering; exit policy still evaluates all errors and configured fail-on-warning. Callable API emits structured diagnostics to caller; annotation formatting belongs to explicit CLI dispatch, never import side effects. Acceptance includes Unicode/path punctuation/multiline messages, duplicate suppression and machine-output purity. Source: [GitHub workflow commands](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands).

Omission release projection: `generate-persisted --omit-runtime-source` writes a separate owned staging tree at `<project>/build/graphql-desk/omitted/<generated_package path>`, never overwriting the live retained generated package. Its generation manifest declares mode `omitted` and the exact required release files. Preserve source-free result/variable/fragment/schema type declarations and ID-only persisted constants. Strip source-literal factory overloads, exact-source AST aliases and retained document constants from this release tree; a schema factory may expose only the generic untyped constructor signature there, and application code in omission mode must import typed persisted constants instead. Source companion runtime files must not import authored modules. All remaining declaration imports must resolve within the projected tree or declared runtime dependencies. The wheel builder takes this staged package instead of the live package, and `check --artifact` validates against the omitted-mode manifest rather than requiring development-only overload files. Including the live Literal-source `.pyi` overloads or authoring package fails artifact verification. Required result/variable aliases remain identical in retained and omitted builds; schema names/field names/type names are not raw executable operation text and need not be stripped. Test runtime `.py` and declaration `.pyi` contents, not only loaded runtime constants.
