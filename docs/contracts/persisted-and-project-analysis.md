# Persisted operations and Python project analysis contract

Planning decisions for PLAN-03/04; implementation and all product acceptance remain open. These rules supplement PERSIST-01, SRC-01, SCAN-01 and EDIT-01 in the [requirements ledger](../parity-plan.md#requirements-ledger). They specify Python equivalents, not a claim that upstream TypeScript mechanisms work in Python. `scan` remains experimental.

## Persisted document bytes, IDs and artifacts

The upstream manifest maps caller-supplied string IDs to documents; generation does not compute, require, or replace a hash ID. Arbitrary opaque IDs are supported. Only IDs beginning `sha256:` receive editor hash validation. Schema identity routes documents to separate configured manifests; it is not included in the GraphQL hash bytes.

Upstream manifest normalization defaults on: parse then GraphQL-print the operation text; remove `_unmask` only from fragment-definition directives. Append explicitly composed transitive fragments in resolver traversal order, each separated by two newlines; deduplicate appended fragments by their stripped printed text. Do not alphabetically sort definitions, selections, arguments, or spreads. The appended-fragment deduplication set does not include inline definitions. `--disable-normalization` retains the original operation text/comments/spacing but still appends printed, stripped, deduplicated external fragments. Other client directives are not stripped by this command. It is not the same as a client transform or the scan definition hash.

Upstream editor hashing has two paths: explicit fragment dependencies are unrolled and deduplicated by printed fragment text; otherwise spreads are followed breadth-first by name from the resolved source fragment collection, including transitive spreads. Final combined text is parsed/printed and hashed with SHA-256 over UTF-8, lowercase hex, prefixed `sha256:` for the inserted ID. Unknown spread resolution produces no hash. The pinned source mutates an initial parsed AST to strip inline `_unmask`, then rebuilds from the original text: inline `_unmask` therefore survives editor hashing, while it is removed in a normalized manifest. Explicit external fragment `_unmask` is removed. A fixture must preserve and explain this upstream discrepancy; do not claim the two algorithms always agree.

Explicit unrolling is breadth-first separately for each top-level dependency in caller order: `[A, B]` where A depends on C produces A, C, B (not A, B, C); deeper A→C→D emits A, C, D before B. Each call contributes its fragment definitions in source order; exact printed duplicates coalesce later. The pinned helper suppresses fragment parse errors; Python retains byte behavior for valid inputs but reports malformed dependencies instead of silently omitting them. Required compatibility fixture: an inline `fragment F on User @_unmask { name }` must remain in editor hash bytes and lose `_unmask` in normalized manifest bytes; an externally composed F loses it in both. The existing nested upstream fixture expects `sha256:2cb43b8f11334b38ac959dd27b697b6a66d9cf0891929f138b2148c6c7ff33ca`; preserve its exact source and print output in acceptance fixtures before asserting a Python match.

The nested fixture's combined input below is passed through GraphQL `print(parse(...))` before hashing (indentation is normalized; no trailing newline is hashed):

```graphql
query GetPokemonNested {
  pokemon(id: "x") {
    ...PokemonAttacks
  }
}
fragment PokemonAttacks on Pokemon {
  attacks {
    fast {
      name
      damage
    }
  }
}
```

Python decision: preserve the two upstream byte algorithms, including the inline `_unmask` discrepancy, under separate names in the shared analysis engine: editor hash input and manifest document bytes. Reuse the same resolver/printer, but never pretend normalization is one function. The editor action and stale-hash diagnostic use the pinned editor algorithm; manifest generation uses the pinned collector algorithm. Keep fragment traversal and duplicate behavior in byte-compatibility fixtures rather than sorting them. Conflicting same-name definitions are validation errors before generation; explicit duplicate identical definitions retain the upstream print result for compatibility. Retain arbitrary explicit IDs; only `sha256:` receives stale-hash diagnostics. Explain that this ID identifies the source/editor normalization, not a promise that the server should independently hash manifest bytes. A server that requires content-addressed IDs must reject the inline `_unmask` mismatch with an actionable build error and request a source rewrite to external masked fragments; never silently rewrite the ID.

Upstream duplicate manifest IDs silently use the last collected document. Python decision: identical ID/content coalesces; same schema/ID with different content is an error naming both locations, and no manifest is replaced. Empty discovery writes `{}` to a configured target so stale operations cannot survive (upstream skips writing an empty manifest). All outputs are staged and atomically replaced after validation; `--fail-on-warn` prevents replacement across the project. These intentional safety differences retain the capability without silently losing operations. Multiple schemas need one target each; a single `--output` cannot ambiguously merge them. Multiple projects must run machine output separately or use each configured output.

For source `query Q { user { id name } }`, the normalized manifest value is exactly `query Q {\n  user {\n    id\n    name\n  }\n}` with no final newline inside the string. Its suggested ID is `sha256:` followed by `hashlib.sha256(value.encode("utf-8")).hexdigest()`. JSON is an object such as `{"chosen-id": "query Q {\n  user {\n    id\n    name\n  }\n}"}` (formatted with two spaces and one file-final newline). A comment or indentation edit leaves the suggested ID unchanged; reordering selected fields changes it. The manifest includes fragment definitions required by the executable document; masking-only `_unmask` is absent. Normalization-disabled mode is an explicit compatibility escape hatch and the editor warns that its stored bytes can differ from canonical hash input.

### Retained versus omitted runtime source

Default is retained source: `graphql.persisted("chosen-id", query)` carries the typed document and ID; adapters may send source and/or ID according to server protocol. No server registry, automatic persisted-query handshake or universal transport is implied by manifest generation. The core object exposes document/ID metadata; client adapters select wire fields. A client that injects `__typename` or transforms directives must apply its declared deterministic transform before registering and hashing the transformed wire document, or disable that transform for persisted requests. The manifest command must fail on an undeclared transform rather than register bytes different from the transport.

Omission is a required explicit generated-module build mode, not destructive rewriting of authored Python. First generate and validate the server manifest from authoring sources. Then generate an importable runtime module of ID-only constants with accompanying `.pyi` result/variable declarations. Application imports those constants; the build configuration excludes authoring modules and server manifests from its runtime wheel. Example artifacts are `graphql_desk_generated/persisted/default.py` containing `GetUser = persisted_id("chosen-id")` and `graphql_desk_generated/persisted/default.pyi` declaring `GetUser: PersistedDocument[GetUserResult, GetUserVariables]`; the constructor carries no raw query. The exact exported symbol spelling follows the [API contract](api-and-types.md). An omission build fails if packaged application imports require excluded authoring modules, if a runtime path requests query text, or if a retained document/fragment source is included accidentally. Source metadata maps the generated constant to its authored operation for diagnostics. Keep retained mode as the default. This generated-module mode supplies the type-only-reference outcome without relying on TypeScript erased generics or runtime string stripping.

Acceptance: compare retained and omitted client variables/result types and request IDs; inspect wheel and imported module constants for removed operation/fragment text; prove excluded runtime string assignments/import dependencies have no side effects; fail unresolved/dynamic references without mutating source or prior output. A generic document client remains usable for retained output; ID-only output requires an adapter/server that supports persisted IDs and must produce a clear error otherwise. Test two schemas, repeated same ID, ID conflict, no operations, invalid parse, unavailable fragment, directive transform, normalization off, Unicode/block strings, nested dependencies and a server registry round trip. No such build currently exists.

## Python discovery and reference identity

Decision: source roots are config-relative include roots (default project directory), with configurable include/exclude globs. Default exclude `.git`, `.venv`, `venv`, `__pycache__`, `site-packages`, build/dist and GraphQL Desk generated/build outputs. Enumerate `.py` files under those roots deterministically, including document-free modules needed by reach analysis; `.pyi` participates in symbol typing, never contributes authored operations. Do not execute project imports, annotations, comprehensions or user functions. External installed dependencies are not scanned. Symlink-resolved files must stay within configured roots and are visited once. Multi-root workspaces have independent config/schema/index ownership; explicit project selection is required for a single machine output target.

Recognize statically imported GraphQL Desk constructors by resolved symbol, including `import ... as`, `from ... import ... as`, package re-exports, explicit `__all__`, and `TYPE_CHECKING` imports used for type-only metadata. Follow absolute/relative imports using configured source roots and package/namespace-package paths; use a visited set/worklist for cycles. Ambiguous star exports, runtime `__getattr__`, import hooks, dynamic imports, monkey patches and conditional reassignments produce an unresolved-reference diagnostic when needed by a document; never guess from a function's spelling. Star imports may resolve only when a literal `__all__` or unambiguous statically indexed export set is known. Index all eligible roots rather than only entry-reachable files, so orphan fragments and disconnected modules remain visible.

Accepted source forms match the [API contract](api-and-types.md): normal/raw single/triple-quoted and parenthesized literals, adjacent literal concatenation, literal-only `+` chains, statically resolvable module-level constant aliases with cycle detection, and plain f-strings without expressions. Accept positional or `source=` input; decode escapes exactly as Python and retain a decoded-to-source range map for every contributing span. Static fragment references use explicit literal tuple/list dependencies and direct names/module attributes across indexed imports/re-exports. No evaluation of interpolated f-strings, `%`, `.format`, environment reads or function-built strings: report actionable dynamic-source diagnostics instead of manufacturing types. Extraction does not guarantee checker literal inference; use the API contract's diagnostic when a resolved string widens to `str`. Standalone `.graphql` is optional extra scope.

Schema routing follows the statically resolved schema-bound constructor. With one default schema, an unbound call uses it; with multiple named schemas an unbound or unknown binding is an error. Never bind by filename coincidence. The same resolved identity drives live typing, manifest collection, rename/references, fragment colocation and scan. Record all definitions, including multi-operation documents, with explicit operation selection for consumers. Co-location associates a consumer with the operation it passes to a supported typed execution boundary, then checks its fragment references/imports through resolved aliases/re-exports; mere matching names do not establish use. Missing/unresolvable dependencies get diagnostics at the spread and declaration, not silent global fragment capture.

Acceptance corpus: direct/aliased/module constructor, shadowed name, package re-export and cycle; source-only disconnected module; excluded generated copies; namespace packages; invalid Python/GraphQL recovering to valid; CRLF/Unicode/raw escaped literal ranges; literal adjacency versus dynamic interpolation; two schemas with same operation/fragment names; file rename/delete/import change; and one consumer selecting a non-first operation. Open-buffer versions override disk only in the editor, while CLI analyzes saved sources and states that boundary.

## Field consumption is a conservative editor heuristic

Default enabled, configurable off; reserved schema field names `id`, `_id`, `__typename` plus user additions never warn. Track query result bindings with known document/result type, normal `await`/direct assignment, aliases, supported `.data` wrappers, tuple unpacking, string subscripts, generated-model attributes, numeric list indexing, `for`/comprehension element bindings and same-file `read_fragment` aliases. Track response aliases as path keys while reserved-key matching uses schema names. Type-derived binding identity must avoid treating structurally similar unrelated dicts as the same operation. Mutations/subscriptions are excluded because cache effects make absence of reads misleading; Python checks the operation AST, rather than copying upstream's substring-based exclusion.

An actual leaf read marks that leaf. Passing/returning/storing/spreading a whole tracked subtree to unknown code marks that subtree consumed; dynamic key access conservatively marks its subtree consumed. No observed same-file consumption means silence, because use may occur elsewhere. An unresolved wrapper or invalid buffer suppresses unused-field findings for that binding and emits an analysis-limit diagnostic only when useful, rather than pretending complete knowledge. Python list iteration/comprehensions supply the equivalent of upstream array callbacks; ordinary callable boundaries are escapes, not interprocedural analysis. No runtime instrumentation is needed. Aggregate unused leaf warnings at their nearest selected parent, preserve source order and point to original field-name ranges; warning ID corresponds to upstream `52005`. Do not offer deletion fixes when directives, fragments or unresolved accesses make removal unsafe.

Fixture: query `{ user { id name email } }`, `result = execute(query)`, `print(result["user"]["name"])` warns for `user.email`, never `id`. Passing `result["user"]` to an unknown function suppresses warnings below `user`; `result["user"][key]` does the same. No local read suppresses the whole document's unused-field warnings. Alias, list/comprehension, nullable guard, wrapper, fragment-unmask, overwritten binding and scope-shadow cases are separate acceptance fixtures. This heuristic does not establish schema field-use counts or prove code is dead.

## Complete scan rules and machine contracts

All eight pinned rules run by default. They rank insights, not validation errors; there are no upstream complexity/depth warning thresholds to invent. Validation and discovery warnings are separate. GraphQL Desk preserves these formulas and outputs, schema-scopes coordinates internally and in graph IDs to prevent different schemas merging the same `Query.field`; JSON references add `schemaName` where needed. That explicit Python correction is not a claim of byte-identical upstream JSON.

| Rule | Input, formula and output data |
| --- | --- |
| `field-usage` | Count each non-introspection schema coordinate once per definition, regardless of repeated aliases. Data: `typeName`, `fieldName`, printed `fieldType`, `deprecated`, optional `deprecationReason`, `count`, `directUsages[{defId,module}]`, transitive operation IDs, `reach{modules,areas,entryPoints}`. Reach unions each selecting/operation module plus its reverse import closure. Weight is reached entry count if graph has entries, otherwise reached module count. Sort count descending, weight descending, coordinate ascending. Unselected schema fields are absent. |
| `input-usage` | Count syntactic enum literals and input object fields using schema input types, including defaults visited in the document; runtime variable values are unknown. Coordinate `Enum.VALUE`/`Input.field`; data `{kind: enum-value or input-field,count}`, weight=count; count descending then coordinate. |
| `deprecated-usage` | Deprecated selected schema fields; deduplicate direct definitions, expand fragments to reaching operations. Data `{reason?,count,operations}`, count/weight=distinct operation count, descending. Orphan-fragment deprecations can have count zero. |
| `orphan-fragments` | A fragment is orphan when never the target of a resolved spread from any definition, not when merely unreachable from an operation. Data `{typeCondition,module}`; no weight. An isolated mutually-spreading cycle is not orphan under this rule (GraphQL validation still diagnoses cycles). |
| `cross-feature-fragments` | Count direct spread occurrences; consumer areas are directories of spreading definitions, relative to project root, root directory labeled `(root)`. Emit only if some consumer area differs from defining area. Data `{definingArea,consumerAreas,spreadCount}`; consumerAreas includes own area if used there; weight=distinct external area count descending. |
| `operation-complexity` | Union distinct selected coordinates through reachable fragments, skipping `__*`; `listFields` counts coordinates whose return type after outer non-null removal is a list. Effective depth=max(own selection-set depth, spread-depth minus 1 plus fragment effective depth), cycle guarded. `score=fieldCount+depth*depth+3*listFields`. Data `{depth,fieldCount,listFields,fields(sorted),score}`; weight=score descending. This is a static ranking proxy, never server execution-cost prediction. |
| `fetch-depth` | Queries only; shortest import-edge distance from any module with no incoming imports. Data `{depth: integer or null,area,module}`; null for unreachable closed cycles; weight=depth when known; depth descending with null last. Mutations/subscriptions absent. |
| `directive-usage` | Count every syntactic directive application before network stripping, including `_unmask`, skip/include/defer and custom directives. Data `{count}`, directive-name reference, weight=count; descending count then name. |

Each datapoint has `{ref,message,data,weight?}`. Stable ties in Python use schema/name/source position, so repeated runs are deterministic. Preserve corpus fields: operations `{id,name,kind,schemaName,module,loc,variables,fragmentSpreads,hash}`, fragments `{id,name,typeCondition,schemaName,module,loc,fragmentSpreads,hash}`; location is authored file with 1-based line/column, variable `{name,type,defaultValue?}` uses printed GraphQL text. Upstream scan hashes each printed definition separately with SHA-256 truncated to 16 hex characters, unrelated to persisted IDs. IDs are schema-qualified operation/fragment names, anonymous sequence IDs, with collision suffixes; Python uses sorted file/source ordering so collisions remain reproducible, and warns on ambiguous conflicting fragment names rather than resolving arbitrarily.

Import edges point importer → imported project module. Default entry modules have no incoming edge; optional config `entrypoints` explicitly replaces that inferred set with project-relative Python paths (unknown/excluded paths are configuration errors). Shortest distance uses BFS; reverse closure includes a module itself for reach. Include isolated eligible modules in Python's graph, even when no documents/imports occur. An import cycle with no incoming entry has null fetch distance; do not manufacture an entry. Areas are project-relative directories (not semantic feature guesses). Validate reach from a three-file chain, a diamond, a cycle and a disconnected file, and explicit entrypoint overrides.

| Mode | Required output and error behavior |
| --- | --- |
| Default terminal | Overview totals and operations-by-kind; schema coverage; ranked rule sections and locators; human warning/progress summary; bounded interactive width, unbounded pipe width. Exact ANSI decoration is not a parity gate, information and ranking are. |
| `--format json` | JSON `{version:1,overview,operations,fragments,rules}` plus Python `warnings` array and explicit `schemaName` on ambiguous references. Overview `{operations,fragments,modules,operationsByKind:{query,mutation,subscription},coverage:{usedFields,totalFields,percent}}`; percent=nearest integer of 100*used/total, or 100 for empty schema. Count schema-qualified coordinates. Full result is two-space JSON plus final newline. |
| `--graph` | Pure `{nodes:[{id,kind,label}],edges:[{from,to,kind}]}`. Node kinds `module`, `operation`, `fragment`, `schemaType`, `schemaField`; edge kinds `imports`, `defines`, `spreads`, `selects`, `onType`. Only selected schema fields/types are materialized. IDs include schema identity for schema nodes. Graph takes precedence over report format. |
| Destination | Machine stdout contains only JSON, human chatter goes to stderr or is suppressed; explicit output file leaves stdout free. Single selected project per machine output. Bad format/config/schema/write error exits nonzero. Findings alone do not fail. Discovery/parse warnings fail only with `--fail-on-warn`; JSON includes them even when progress is silent. |

Python JSON's warning field and schema qualification are documented additive corrections to upstream version-1 shape; consumers must ignore unknown fields. The upstream graph does not carry a version field, so do not add an undocumented wrapper. No machine output may leak configured authentication headers.

Acceptance examples: selecting `Query.users: [User!]!` and `User.name` gives depth 2, 2 distinct fields, 1 list, score `2+4+3=9`; selecting `User.name` twice in one definition contributes one field usage, while a second definition contributes a second usage. A fragment used only by another orphan fragment is not itself orphan; a query two imports from root has fetch depth 2. Selecting 2 of 3 eligible schema fields reports 67% coverage. Snapshot every rule's complete data, terminal information, JSON/graph topology, repeated-run ordering, duplicate schema coordinate isolation, missing schema, invalid source, fail-on-warning and clean machine stdout. Fixtures must compare ordinary cases to pinned upstream output and mark the deliberate safety/correctness differences above.

## Decisions still awaiting evidence

No irreducible user product choice remains for PLAN-03/04: these defaults preserve requested capabilities. Printer compatibility, client adapter transform behavior, omission build safety, static resolver coverage and conservative field-use behavior still need implementation acceptance tests. They are product gates, not proof obtainable by writing this contract. The parent package's support/version matrix and concrete API spellings must cross-reference these rules before planning is declared complete.

Cross-contract build binding: invoke `generate-persisted --omit-runtime-source` with dedicated configured `authoring_roots`, generate `<generated_package>.persisted.<schema>` constants, package only application/generated modules, then `check --artifact PATH.whl`. The config/CLI contract specifies exact layout, source-root/glob syntax, failure and artifact checks; those defaults govern this discovery algorithm. Generated constants may not import authoring modules. No hand-maintained exclusion is assumed silently: artifact verification is required for omission acceptance.

Omission includes a source-free release projection under `build/graphql-desk/omitted` as specified by the lifecycle contract: exclude live Literal-source factory overloads and exact-source AST declarations as well as runtime source strings. Preserve result/variable aliases and ID-only constants. Package that projected generated tree; artifact checks use its omitted-mode ownership manifest. Packaging the live generated tree would leak source through `.pyi` overloads and must fail.
