## Findings at a glance

The memos correctly make operation/result and variable typing, live editor feedback, fragments, persisted documents, schema workflows, CLI checking, scan, and fragment fixture helpers parity topics. The source audit adds several facts that affect acceptance criteria:

- The public package surface includes root exports and `./cli`, `./internal`, `./testing`, and `./ts-plugin` subpaths. Root exports include `parse`, `graphql`, `initGraphQLTada`, `readFragment`, `maskFragments`, `unsafe_readResult`, and type utilities. `readResult` is available from `gql.tada/testing`, not the root entry point. See [root exports](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/index.ts), [package export map](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/package.json), and [testing exports](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/testing.ts).
- Fragment masking is entirely type-level. `readFragment`, `maskFragments`, `readResult`, and `unsafe_readResult` return the input data unchanged at runtime. They do not validate, rewrite, or wrap response JSON. The package's masking UX is compile-time access control plus typed identity helpers, not runtime masking. See [API implementation](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/api.ts) and [testing helper implementation](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/testing.ts).
- `graphql.scalar()` is also type-level only: at runtime it returns the supplied value without scalar/enum validation. It covers custom scalars, enums, and input-object types; custom enum mapping was added in 1.5.0. Treat it as a static typing helper, not a coercion or serializer API. See [scalar API and implementation](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/api.ts) and [`api.test-d.ts`](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/__tests__/api.test-d.ts).
- A `graphql()` document with more than one definition is typed from its **first definition**. Both result inference and variables use definition zero; following fragment definitions are available to fragment resolution. This is a real upstream wrapper behavior, not standard per-operation selection. Python should not silently type a different operation than the developer intends; explicitly model each operation or diagnose ambiguous multi-operation documents. See [selection inference](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/selection.ts#L270), [variables inference](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/variables.ts#L116), and [runtime document construction](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/api.ts#L310).
- The CLI's generated schema output (`generate-output`) is the schema/introspection type input required to set up typed `graphql()`. It does **not** generate per-operation result/variable types. Those are inferred dynamically by the TypeScript type system; `turbo` optionally snapshots current document types to accelerate later type evaluation. Keep required schema typing and live operation typing separate from the optional turbo-like cache. See [CLI docs](https://gql-tada.0no.co/reference/gql-tada-cli) and [workflow docs](https://gql-tada.0no.co/get-started/workflows).
- `scan` is present and has rule/output/graph tests in the current source, but the docs still label it **experimental**. Its source scans GraphQL calls discovered in TypeScript project source files and constructs a TypeScript-module import graph; it is not a standalone `.graphql` file scanner. Do not use the memos' illustrative `.graphql` scan case as evidence of upstream behavior. See [scan command source](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/packages/cli-utils/src/commands/scan/thread.ts), [scan docs](https://gql-tada.0no.co/reference/gql-tada-cli#scan), and [scan tests](https://github.com/0no-co/gql.tada/tree/cfe64f433bd29ff6f79e462596389b81c6e01aec/packages/cli-utils/src/commands/scan/__tests__). The `init` and `doctor` CLI commands are separately marked work in progress.

## Semantics to carry into Python parity

1. **Type values and key presence are different.** Operation result nullability follows the GraphQL output type wrappers. A field conditionally included with `@include`, `@skip`, or `@defer` may be absent; this is not the same as a present nullable field. Input variables are optional keys if nullable or defaulted; a non-null variable without a default is required. Input-object fields with schema defaults can be omitted. Preserve omission versus explicit `None` in Python typing. See [selection implementation](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/selection.ts), [variables implementation](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/variables.ts), and [variable tests](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/src/__tests__/variables.test-d.ts).
2. **Aliases control response keys.** Result types use the response alias where present, not the schema field name. Abstract selections need possible-type-aware branches; `__typename` can be used to narrow. Verify actual access through Pyright/Pylance rather than only snapshotting a generated type string.
3. **Custom scalars are mappings, not serialization.** Configured mappings affect both selection result fields and variable/input types. They do not implement JSON encoding/decoding. Python parity should specify the typing/coercion boundary instead of implying that a mapped `datetime` gets serialized.
4. **Client-controlled nullability exists upstream.** `@_optional` and `@_required` on fields override inferred nullability/presence for client-controlled nullability implementations. They are non-standard gql.tada directives and need explicit support or a named, visible non-parity decision. The type tests cover these in `selection.test-d.ts` / API fixtures. [1.1.0 history](https://github.com/0no-co/gql.tada/blob/cfe64f433bd29ff6f79e462596389b81c6e01aec/CHANGELOG.md).
5. **Multiple definitions need deliberate Python behavior.** `getDocumentType` reads `definitions[0]`; `getVariablesType` also reads definition zero, and fragments following it are indexed for spread resolution. Multiple operation definitions do not get independently typed by one `graphql()` result. For parity, provide one typed operation per selected operation or precise selection by name; diagnose ambiguous documents instead of assigning every definition the first operation's type. Keep fragment-only documents supported.
6. **Fragments are linked explicitly at authoring time.** `graphql(source, fragments)` appends fragment definitions from the supplied document values. Colocated-fragment diagnostics inspect TypeScript imports/exports and are an opinionated GraphQLSP diagnostic, not core `graphql()` runtime behavior. A Python implementation needs its own Python import/source index; merely parsing all files is not equivalent.
7. **Type checking is the validation layer for scalar helper / masks.** Runtime helpers are identity values and do not validate data or scalar values. Any runtime validation introduced by Python can be useful, but it is extra behavior and must not be the only path to static editor parity.

## Missing parity rows to add explicitly

1. **Package entry-point parity:** Python package equivalents for the root API and optional sub-APIs, including parser/document type extraction, test utilities, CLI library API, editor integration, and any public internal entry point that GraphQL Desk chooses to support. Do not expose internals accidentally; document any intentional consolidation.
2. **Operation document and client interop:** typed result/variable extraction for a document; per-operation binding for multi-operation source; Python client compatibility contract that retains ordinary client/network/cache behavior.
3. **Scalar helper contract:** static checking of scalar, enum, and input-object values; configurable aliases/mappings; no false claim of runtime validation or serialization.
4. **Optional response members:** `@include`, `@skip`, `@defer`, fragment optionality, and custom `@_optional` / `@_required` behavior, independent of schema nullability.
5. **No-runtime fragment helpers:** mask/unmask and fixture typing without copying/wrapping the data; explicit safe versus unsafe fixture helper contracts.
6. **Source/call form scope:** upstream gql.tada authoring is TypeScript `graphql()` source strings/template literals with supplied fragment document arguments; its scan/check/persisted commands operate on TypeScript project files. GraphQL Desk's optional `.graphql` support would be an additional form, not proof of parity alone.
7. **CLI maturity and source formats:** provide equivalent `init`, `doctor`, check, schema acquisition/output, persisted manifest, scan/report/graph, and turbo-like cache affordances; label mature/stable, experimental, and work-in-progress equivalents. Scan must define how Python imports/exports and source forms map into module reachability.

## Exact acceptance tests for GraphQL Desk

These are proposed tests; no GraphQL Desk code was changed or run during this audit.

1. **Exports and operation extraction:** Import public package APIs documented as supported. Given schema + one named operation, assert result and variable aliases are usable from generated Python types and `ResultOf`/equivalent helpers; a fragment passed as a fragment target is rejected as an operation if the API requires operation-only. Verify client operation execution continues through the chosen existing Python client.
2. **Multi-definition safety:** Put two named operations and their fragments in one source. Assert each operation is bound by its own name and produces distinct result and variable types; an anonymous/mixed document follows a documented selection rule. No operation silently receives definition-zero's result/variables. Add a fragment-only document fixture.
3. **Result shape matrix:** Assert aliases become response keys; nested object/list/null wrappers survive all four outer/item nullability combinations; union/interface inline fragments narrow on `__typename`; enum output is finite; custom scalar mapping affects output type only and does not imply serializer behavior.
4. **Variables and input defaults:** `$required: ID!` is required; `$defaulted: Int! = 10` may be omitted but rejects `None`; `$nullable: Int` may be omitted or `None`; input object required, nullable, and defaulted fields distinguish omission from explicit null; reject invalid enum/input values and wrong list item/null positions.
5. **Conditional selections:** For fields and fragment spreads gated by `@include`, `@skip`, and `@defer`, generated response shape permits key absence while retaining field-value nullability. Include directive variable type/requiredness and default cases. Verify `@_optional` and `@_required` against the documented custom override semantics, including nested wrappers.
6. **Fragment masking:** Parent operation permits direct access only to directly selected fields and a typed fragment reference for spread-only fields. `FragmentOf` consumer shape accepts the reference; `read_fragment` exposes only fragment payload after access. Test nullable, optional, arrays of nullable items, nested fragments, interfaces/unions, aliases, repeated spreads, and global/per-fragment unmasking. Test both static Pyright/Pylance diagnostics and runtime object identity.
7. **Fragment fixture helpers:** Safe `read_result` recursively checks supplied direct/transitive fragment fixture fields and preserves references for omitted fragment dependencies; missing/wrong fields fail static checks. `mask_fragments` accepts fixture result shapes and preserves data identity. The unsafe helper is clearly named, permits the documented cast, and does not claim nested verification.
8. **Scalar helper parity:** For builtin/custom scalar, enum, and input-object names, valid values pass static checks and invalid values fail. Runtime call returns the identical object and performs no coercion/validation. Include configured enum remapping and optional/null values.
9. **Schema/output/live typing separation:** From SDL, introspection JSON, or authenticated endpoint, schema acquisition writes deterministic SDL and generated schema typing. While a GraphQL operation is unsaved, its Python result/variable types and diagnostics update live. Verify `turbo` disabled/enabled yields equivalent results; only cache latency differs.
10. **Persisted documents:** Persist by explicit ID and by hash code action; stale IDs are diagnosed and action computes the agreed SHA-256 over the normalized document. Support preserved runtime document and omitted-definition runtime document with identical static types. Manifest includes transitive fragment definitions once, stable normalized text by default, and duplicate IDs/conflicts are surfaced. Confirm no transport/server registration is implied.
11. **Project scan:** On the required embedded Python call form, report operations/fragments keyed to the correct schema, field/input/deprecation/directive usage, complexity/depth, orphan/cross-feature fragment findings, and stable JSON/graph output. Follow import reachability across aliases/re-exports per documented limits. `--fail-on-warn` behavior matches editor/CLI rule IDs. Standalone `.graphql` discovery/source-range tests apply only if GraphQL Desk chooses to add that extra input form.
12. **Check/config/maturity:** Shared config drives editor and CLI. Test severity filtering, fail-on-warning, schema/scalar config errors, CI annotations, doctor failures, and init behavior. Mark scan experimental-equivalent rules and any work-in-progress setup/doctor behaviors so maturity is not hidden.
13. **Source update recovery:** Edit an operation, fragment, schema, or scalar config without saving; verify dependent types/diagnostics update and stale ones disappear. Invalid/incomplete text must not silently leave old types looking current; repaired input recovers. This tests GraphQL Desk's Python editor outcome, not gql.tada's TypeScript mechanism.

## Limits of this verification

This was source/docs/test inspection, not a fresh install and execution of the upstream test suite. The exact npm tarball contents were not unpacked; npm metadata confirmed latest published version `1.11.4`, and repository tag/source at that version was inspected. This memo audited gql.tada; the separate [GraphQLSP source audit](graphqlsp-source-audit.md) supplies pinned plugin/extension inspection. I did not independently test all complex fragment overlap, malformed-buffer, or GraphQL specification edge cases; the acceptance list identifies those required GraphQL Desk checks.
