# Editor snapshot analysis boundary

`graphql_desk.editor_analysis.analyze_editor_snapshot(request)` accepts explicit JSON-shaped facts and returns JSON-shaped analysis. `analyze_editor_json(text)` validates and serializes the same boundary. Neither function reads files, discovers projects, starts processes, imports project code or contacts schema endpoints. A trusted caller supplies snapshots and owns cancellation, process transport and freshness checks before publication.

The request has exactly `request_id`, `modules`, `bindings` and `schemas` fields. Module records carry `project`, `module`, local `uri`, integer `version`, `source` and boolean `is_package`. Binding records carry actual `ProjectBindings` facts: `project`, `schemas`, `default_schema` and `factories`; factory records have `module`, `export` and `schema_name`. Schema records carry `project`, `schema_name`, local `uri`, integer `version`, opaque `token`, `format` (`sdl` or `introspection`) and `text`. No configuration or schema name is inferred from filenames. Unknown fields, malformed records, duplicate JSON keys, nonfinite JSON numbers, duplicate source identities and conflicting configured identities reject. File and untitled URIs are metadata, not permission to read them.

The response repeats `request_id` and source/schema identity facts, and returns `calls` and `diagnostics`. Calls contain the actual source resolver's identity, schema metadata, source text, operation selection, version dependencies and ordered fragment references. Their `map.codepoint` and `map.utf16` arrays serialize the existing decoded/host mapping atoms separately, retaining linear runs, indivisible escapes, zero-output continuations, gaps and repeated/imported origins. Each host span retains its module identity and version. UTF-16 endpoints are converted from actual map endpoints; atomic interiors are not assigned guessed positions.

Successful fragment indexing adds a call's `index` with schema/token identity, selected operation, primary fragment, ordered definition facts and transitive dependencies. Definition facts keep their owning document identity and printed text. Printed text has no implied authored offsets: editor consumers must locate nodes in each original call source and use its map. A failed GraphQL parse or fragment check leaves `index` null while preserving resolved source and maps for online completion. Invalid or incomplete Python produces source diagnostics without precise resolved calls; lexical highlighting is a separate conservative fallback.

Only a supplied binding's actual default schema installs the unbound schema context. Supplied SDL/introspection is validated in memory. Missing contexts remain explicit diagnostics; invalid schemas reject without echoing their contents in the exception. This boundary does not acquire current buffers or verify current disk/config/schema state. Its caller must compare every relevant version and schema token, and must not execute analysis in an untrusted workspace.

Tests cover the real resolver/index/map pipeline, invalid-to-valid recovery, explicit factories and named routing, imported fragments, Unicode/CRLF/escapes/repeated origins, empty boundaries, SDL/introspection and malformed JSON facts without source IO. This is a read-only foundation for #39/#40. VS Code activation, snapshot acquisition, worker launch, provider registration, live editor acceptance and the unresolved production analysis adapter remain separate work; no broad editor or live-typing gate is passed.
