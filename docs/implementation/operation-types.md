# Operation declaration renderer

`graphql_desk.operation_types.render_operation_types(schema, source, *, name, operation=None, scalars=(), enums=())` returns a complete Python declaration module containing the schema aliases, `<name>Variables` and `<name>Result`. It validates the document before rendering; select an operation explicitly when the document contains several.

The initial subset supports query/mutation/subscription roots, nested object selections, aliases, merged compatible repeated fields, built-in scalars, enum literals and literal `__typename`. List and null wrappers are preserved. Nullable variables and variables with defaults may be omitted; a non-null variable with a default still rejects an explicit null. Generated declaration names must be safe, normalized Python identifiers and must not collide with schema or other generated declarations.

Union and interface selections produce concrete result alternatives, including inline fragment conditions. Fields retain the types declared at their authored scope, including interface nullability. Explicit or aliased `__typename` selections are required literal discriminators. Abstract alternatives also expose an optional canonical `__typename` aid unless an authored response key already owns that name; an alias such as `__typename: id` keeps its actual ID type. The aid does not add a runtime response field. Abstract types with no possible implementations use a private `Never` alias while preserving list/null wrappers.

Configured scalar mappings distinguish variable/input and result/output aliases; enum remappings apply in both directions. Mapping facts and limitations follow the [schema renderer](schema-types.md). Named fragments, all directives, unmapped custom scalars and introspection object selections currently raise errors. Unsupported semantics never become `Any`. The schema renderer supplies closed oneOf input alternatives and preserves variable omission/default behavior. This function produces declarations only: it does not attach them to factories, execute requests, coerce responses, write files or refresh Pylance.

Tests execute generated modules, compare real GraphQL response aliases, and check both valid and invalid bindings with strict mypy/Pyright. The abstract selection rules were checked against pinned gql.tada selection source. These are foundations for #22 and #32, not completion of TYPE-01 or the live-typing gate. Named-fragment integration keeps #32 open. Remaining semantics and integration are tracked separately in the [full inventory](../feature-tracking.md).
