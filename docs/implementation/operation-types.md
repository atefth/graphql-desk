# Operation declaration renderer

`graphql_desk.operation_types.render_operation_types(schema, source, *, name, operation=None, scalars=(), enums=(), client_directives=())` returns a complete Python declaration module containing the schema aliases, `<name>Variables` and `<name>Result`. It validates the document before rendering; select an operation explicitly when the document contains several.

The initial subset supports query/mutation/subscription roots, nested object selections, aliases, merged compatible repeated fields, built-in scalars, enum literals and literal `__typename`. List and null wrappers are preserved. Nullable variables and variables with defaults may be omitted; a non-null variable with a default still rejects an explicit null. Generated declaration names must be safe, normalized Python identifiers and must not collide with schema or other generated declarations.

Union and interface selections produce concrete result alternatives, including inline fragment conditions. Fields retain the types declared at their authored scope, including interface nullability. Explicit or aliased `__typename` selections are required literal discriminators. Abstract alternatives also expose an optional canonical `__typename` aid unless an authored response key already owns that name; an alias such as `__typename: id` keeps its actual ID type. The aid does not add a runtime response field. Abstract types with no possible implementations use a private `Never` alias while preserving list/null wrappers.

Field `skip`, `include` and schema-legal `defer` directives make keys optional even with literal conditions. An unconditional repeated scalar selection guarantees key presence. `required`/`_required` remove outer nullability; `optional`/`_optional` add it, with required taking precedence and list-item wrappers unchanged. Typename remains a literal under nullability overrides, matching the pinned source. `stream` has no special result-type effect. The renderer suppresses unknown-directive errors only for GraphQLSP's pinned built-in client names and explicit `client_directives` names. Schema-declared directive arguments, locations and variables remain validated; no directive declarations are injected or execution behavior invented.

Conditional inline fragments and repeated conditional composite selections produce absent/present alternatives, retaining independent selected fields. Affected alternatives and their descendants use closed dictionary shapes so both checkers reject partial combinations, including wider pretyped values. Syntax occurrences vary independently even when conditions use the same variable or literal; this is conservative presence inference, not Boolean evaluation. A pinned TypeScript probe and real GraphQL execution showed upstream intersections can require omitted child fields; these alternatives preserve actual omission instead.

Equivalent alternatives coalesce incrementally. More than 64 alternatives at one conditional selection or 256 conditional alternatives across one render raises an explicit error without returning partial output. Ordinary conditional fields retain `NotRequired` behavior. Repeated simultaneously active fields with differing nullability overrides still reject. Named-fragment integration and configuration/consumer integration keep #33 open.

Configured scalar mappings distinguish variable/input and result/output aliases; enum remappings apply in both directions. Mapping facts and limitations follow the [schema renderer](schema-types.md). Named fragments, unmapped custom scalars and introspection object selections currently raise errors. Unsupported semantics never become `Any`. The schema renderer supplies closed oneOf input alternatives and preserves variable omission/default behavior. This function produces declarations only: it does not attach them to factories, execute requests, coerce responses, write files or refresh Pylance.

Tests execute generated modules, compare real GraphQL response aliases, and check both valid and invalid bindings with strict mypy/Pyright. The abstract selection rules were checked against pinned gql.tada selection source. These are foundations for #22 and #32, not completion of TYPE-01 or the live-typing gate. Named-fragment integration keeps #32 open. Remaining semantics and integration are tracked separately in the [full inventory](../feature-tracking.md).
