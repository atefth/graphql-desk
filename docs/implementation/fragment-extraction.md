# Fragment extraction

Extraction replaces a complete selected sibling field set with a fragment spread, preserves any selected external fragment dependencies, and validates the transformed document before returning versioned edits. A selected spread may resolve through one uniquely composed local fragment dependency closure; extraction reuses that root binding once and refuses multiple possible roots.

At module scope, the fragment stays a named Python binding immediately before the query. In a module-level `if`/`elif`/`else`, loop, `try`/`except`/`else`/`finally`, `with`, or `match` suite, the fragment `gql(...)` call is placed inline in the operation's `fragments` list so both calls remain in the same execution branch and static source discovery can resolve them. Inside ordinary or async function bodies, including nested function definitions and assignments nested under those same control-flow suites, the fragment call is also placed inline, except for the narrow local-binding case below. Direct methods of class statements directly in the module body use the same inline form. Nested operation calls are eligible only when their callable and source/composition inputs resolve without enclosing-function locals. Class-body assignments and methods on classes nested in functions, classes or module control-flow suites remain unsupported.

Inside a function, a literal static local fragment may be assigned once by a direct `Assign` or `AnnAssign` to one simple name, then referenced only as a direct element of one later operation's literal `fragments` list or tuple in the same straight-line suite. The source resolver accepts it only if it parses as exactly one fragment definition. Branch-defined, rebound, aliased, captured, dynamic, or otherwise non-fragment locals remain unresolved; this does not enable general Python local-name resolution.

Function-scope support covers direct `Assign` and `AnnAssign` statements whose target is a simple name and whose factory is a trusted `graphql_desk.gql`/`graphql` import, an exact configured factory binding with `fragment_composition=true`, a statically imported `graphql_desk` module alias (`desk.gql`, `desk.graphql`, or `desk.init_graphql`), or a known module-level `init_graphql` result. Per-schema generated factories are marked composition-capable automatically; custom configured templates require the explicit `template_fragment_composition = true` opt-in, whose contract is that the callable accepts GraphQL Desk's `source=` and `fragments=` API, preserves document identity, and composes those fragments. Merely configuring a custom factory is insufficient. Configured factories must use a direct absolute `from module import export` (with an optional local alias); relative imports, module-qualified custom calls, unconfigured names, default-off custom factories, and local factory aliases remain unsupported. A module alias must have one binding and may only be used as the receiver of a direct GraphQL Desk factory call; any other reference can escape to a mutator or setter alias, so extraction is refused. Any `exec` or `eval` call also refuses extraction, whether direct, imported from `builtins`, accessed through a `builtins` module alias, or copied by simple name assignment. Any explicit `__builtins__` name reference also refuses extraction entirely. The extractor refuses module-qualified mode when it sees the `sys` module registry (including aliases made by simple name assignment), access through `getattr` or `vars` (direct, via `builtins`, imported under an alias, or copied by simple name assignment), `globals()` or `locals()` access (direct, via `builtins`, imported under an alias, or copied by simple name assignment), `sys.__dict__`, standard `importlib.import_module` (including imported function and module aliases copied by simple name assignment), or built-in `__import__` calls (direct, via `builtins`, imported under an alias, or copied by simple name assignment). These known lookup routes can return the shared mutable module or namespace. The check is deliberately bounded: arbitrary wrappers and attribute-based alias tricks, including `object.__getattribute__`, are not fully analyzed. Class bodies and class methods outside the supported direct-module class case, along with global/nonlocal declarations, remain unsupported. The provider preserves suite indentation and the source newline style and rejects stale or cancelled edit plans.

Inline-only fragment dependencies are assigned immediately before the operation in their original source order, and the same bindings are reused from both the operation and extracted fragment. This preserves each dependency's identity without evaluating its factory twice or changing evaluation order. Nested resolved spreads reuse the unique direct root fragment binding whose closure contains them; duplicate roots are ambiguous and extraction is refused. The operation factory must satisfy GraphQL Desk's `source=`/`fragments=` composition contract; custom factories require the explicit opt-in above.

This remains a bounded #51 slice. Captured-local cases outside statically resolvable inputs and broader selection/ambiguity acceptance remain open; it does not pass a broad parity gate.
