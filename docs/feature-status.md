## Active work and observed blocker

#27 remains open after configuration/discovery/selection/ownership/routing and explicit external-root scope foundations: command dispatch/overrides, enumeration/freshness, authenticated-loader and symbol integration remain open. #28 provides module, factory/schema binding facts and versioned fragment references. #29 decoded maps and #34 fragment indexing have merged; navigation/edit and masked-renderer consumers remain open. #31 is complete for closed oneOf input rendering and validation fixtures. #30 provides mapping declarations; complete static symbol resolution and doctor/report integration remain open. Runtime construction and explicit local schema loading are implemented; these do not establish precise factory inference or complete schema workflows.

#22 provides the initial operation declarations; #32 adds abstract alternatives and inline conditions. #33 adds field directives and correlated conditional shapes; explicitly unmasked named fragments consume #34 index facts. Masking and generated/live configuration integration keep these advanced stories open. #23/#24 track the actual owned-buffer adapter and isolated host harness. In real VS Code1.141.0 and1.142.0 tests, publication and disk isolation work, but restoring original text leaves the stub dirty. A resource-unbound revert command cannot safely target only the owned document; manual Save All can also persist an overlay. The adapter is not merged as production and those issues remain blocked. The new harness did not run Pylance because no prepared isolated extension environment was provided. Earlier narrow Pylance research does not settle cleanup.

## Required post-live work versus optional extras

Persisted operations and independent editor conveniences are **required** and begin immediately after live typing passes, in parallel where independent. Fragment/remaining editor, schema/CLI/project, then performance/release acceptance follow. These are not optional backlog items.

| Extra | Status / classification |
|---|---|
| Standalone `.graphql` authoring/discovery | Optional extra; not started. Embedded static Python remains required |
| Persistent turbo cache and its CLI | Optional extra; not started. Correct live inference and incremental recomputation cannot depend on it |
| Saved client/model generation | Separate optional integration/evaluation; not implemented. Turms/Ariadne research does not select a backend. Isolate tools; Ariadne0.19 cannot share core3.3 environment |
| Additional editors/unclaimed platforms | Optional evaluation only; no support promise without tests. Browser-only constraints and remote-host verification remain explicit |

APQ/server registration and a new runtime transport are not GraphQL Desk parity deliverables. Existing clients remain external; required typed-document client interoperability is tracked under API-01. See the [canonical plan](parity-plan.md) and [contracts](contracts/api-and-types.md) for exact acceptance and maturity labels.
